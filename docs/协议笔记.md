# 85A 服务端协议笔记

以下结论来自服务端源码阅读 + 实机抓包验证，只记录字段与判据，不含密钥。

## 包结构

```
13 字节头: [0]=0x01  [1:3]=sendType(LE)  [3:7]=outSize(LE, 头+载荷)
           [7:11]=hash  [11:13]=sendIndex
载荷: cipher.Encrypt(sendType, raw)
```

**载荷长度必须是 16 的倍数**，否则加密直接报 `data not multiple of block size`，
而调用处若不检查错误，就是「包没发出去但日志一切正常」——踩过两次。

## 命令号对照

| 命令 | 含义 | 载荷 | 判据 |
|---|---|---|---|
| 35 | SET_USER_POSITION | `x(2) y(2) dir(1) context(2) pad` | 要求 `state == 3`；成功后同区域广播 NOTI 22 |
| 36 | SET_USER_AREA | 有效 11B，补齐 16B | `village, area, x, y, dir, gate_village, gate_area` |
| 37 | FINISH_LOADING | — | 曾被误当位置包，客户端不更新坐标 |
| 85 | CREATE_PRIVATE_STORE | `village area x y doll_slot(2)` | `state==3`、非 PvP、不在 gate area（否则 error 62）、village/area 必须与当前一致 |
| 88 | MOVE_TO_GATE | — | 不是开商店，曾被误用 |
| 234 | CREATE_DISJOINT_STORE | 分解机摊位 | 成功时不回包，只广播 NOTI 206 |

> 有商贸许可证（`member_premium.pre_type = 8`）时 `doll_slot` 必须传 `0xffff`，
> 没有证时必须传真实娃娃槽位，两者搞反会被拒（error 63）。

## 可见性

`charac_stat.visible_flags` 的 bit0 决定是否向同区域广播。
为 0 时 `move_position` 只把包回给本人，表现就是「机器人在动、玩家看到的是静止残影」。

## 聊天

- `chat_type 15`（全服喇叭）要求背包里有道具 `2660655`，服务端组 0x76 包后 `send_all`
- `chat_type 13` 要求道具 `37`
- 缺少道具时服务端静默丢包，不返回错误

## 加密

- 真实客户端：`Encryption::Encrypt` 逐字节 `b[i] ^= rnd; b[i] = ror(b[i], (rnd >> 8) & 7)`，
  并且把多条命令拼进同一个 TCP 段整段加密
- 工具侧：Anubis 分组加密

两条通道不同，所以抓包拿不到可以逐字节复刻的明文单命令包——这也是
「假人走路动画 / 个人商店」没能完全复刻的根因。
